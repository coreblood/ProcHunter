ProcHunter — Changelog
======================

v1.5.1 (2026-09-11)
-------------------
LIVE-REALM EXTRACTION FIX — Ctrl+Right-click looked like a plain
withdraw because the live realm never answers ICEXSRC; it speaks a
different wire dialect for bag proc queries.

- The locate stage now asks in BOTH dialects: ICEXSRC (old pack) and
  ICINV (live realm).
- The parser understands both replies: classic ICEXI rows, and the
  live realm's ICITEM:B:<bag>:<slot> headers followed by
  ICIPROC:<spell>:<trigger> rows, closed by ICINVEND. Only rows under
  the header of YOUR pinned bag slot are read; equipped-gear headers
  and other slots are ignored, as is ICIPROCBP/FACT/SRC/STAT noise.
- If a realm ever answers both dialects, duplicate procs are deduped.
- Everything downstream is untouched: consent dialog, slot
  re-verification at confirm, ICUNLOCK, live tick flip.

/reload suffices.

v1.5.0 (2026-09-11)
-------------------
EXTRACT FROM THE LIST — Ctrl+Right-click a row to learn one of its
procs, end to end:

- ProcHunter withdraws one copy, identifies the EXACT bag slot it
  landed in (bag snapshot diff: only a slot that newly gained the
  item can ever be destroyed — a pre-existing, possibly imprinted
  copy is never touched), asks the extraction picker (ICEXSRC ->
  ICEXI ... ICEXIEND) for the copy's exact spell and trigger, and
  opens a NAMED CONSENT DIALOG.
- The dialog lists the copy's procs; ones already unlocked are
  greyed out, the first learnable one is pre-selected, and the
  warning is explicit: "This DESTROYS the withdrawn copy. One proc
  per copy." Extraction is free on this realm (Scrolls of Extraction
  are retired) — nothing else is spent.
- Confirm re-verifies the bag slot at the moment of truth (any drift
  aborts with nothing destroyed) and sends ICUNLOCK. On the server's
  ICUNLOCKED reply the proc joins your collection instantly and the
  item's tick flips green live — Wardrobe unlocks made outside
  ProcHunter are absorbed the same way.
- Every stage has a timeout that aborts loudly with the item safe in
  your bags; Cancel does the same. If every proc on the copy is
  already unlocked, the confirm button is disabled and the copy
  simply stays with you. One flow at a time; live progress in the
  status line.

v1.4.0 (2026-09-11)
-------------------
Built from the dissected server addon pack (uploaded 2026-09-11):

- EXTRACTION TICKS: a green tick left of the item name when every
  proc on the item is already in your unlocked collection; a dimmed
  yellow tick when only some are. Judged per proc NAME, so owning any
  rank of a proc counts that proc as unlocked. ProcHunter requests
  the account collection itself (ICCOLL -> ICCOLLROW stream, still
  ordinary addon messages) on open and Refresh (60s cooldown), and
  absorbs Wardrobe streams triggered by other addons for free. The
  row tooltip states it in words: all / N of M / none; the status
  line shows "awaiting extraction data" until the first stream lands.
- WITHDRAW PINNED: the dissected Core.Withdraw(itemRow, count) takes
  the item's own row table and honors the count (sent as exact text
  per kirei's own overflow note), so any amount is now ONE proper
  call. The old guess-routes that could never work are deleted;
  Core.Send with the raw verb and the raw wire send remain as
  fallbacks, and the verify loop stays as a bag-space safety net with
  honest "N of M (stopped)" reporting. Remembered route numbers from
  older versions are reset once (schema migration).
- Wire truth, for the record: same REAGENTBANK prefix, but vault
  snapshot replies ride kirei's native pipe (the addon-message
  fallback was removed server-side) — which is why the UNC listener
  heard silence while UncappedVault.items stayed fresh. Our VLTGET
  is still heard and nudges kirei's addon to refresh the very table
  we read, so it stays.

v1.3.1 (2026-09-11)
-------------------
Withdraw semantics INVERTED after v1.3.0's whole-stack default filled
102 bag slots with Twilight Scales on a 17k stack:
- Right-click now withdraws exactly ONE. Always. No loop, no bulk.
- Shift+Right-click opens an amount dialog: type how many (Enter or
  the Withdraw button confirms, Escape or Cancel aborts; the amount
  is clamped to the stack count, and the item is re-checked against
  the live list on confirm). The target loop then pulls exactly that
  many, with the same live progress and honest "N of M (stopped)"
  reporting as before.
Bulk can no longer happen by accident — it always requires typing a
number.

v1.3.0 (2026-09-11)
-------------------
- FIX: withdrawing a stack now delivers the WHOLE stack. The live
  withdraw route ignores the count and moves one copy per call, so
  withdrawal is now target-based: the proven route is re-fired on a
  ~0.9s cadence, measuring the actual delta each cycle, until the
  requested count has moved or the row is gone. If deliveries stop
  mid-way (bags full, refusal) it stops and reports "N of M
  (stopped)" instead of pretending it finished. Shift+Right-click
  (withdraw one) unchanged. The status line shows live progress
  ("withdrawing <item> 3/20...").
- FIX (flat filter): any PERCENTAGE bonus now classifies as a real
  effect and stays visible ("Improves critical strike damage by
  3.15%") — only plain-number flat stats are hidden. Consequence:
  "chance to hit by 1%"-style lines are also visible again.
- Resizable window: drag the grip in the bottom-right corner
  (430x240 min, 1200x900 max, size saved). Row count follows the
  height and the name column stretches with the width.
- Look options (Interface -> AddOns -> ProcHunter): window opacity
  slider (20-100%), font size slider (8-18), and a font button
  cycling the client's four built-in fonts (Friz Quadrata, Arial
  Narrow, Skurri, Morpheus). All saved.
- Still queued, blocked on the current server addon pack being
  uploaded: green tick for already-extracted procs (no data source
  exists client-side without dissecting where the extraction
  collection lives), and pinning the withdraw route properly.

v1.2.0 (2026-09-11)
-------------------
- Right-click a row to WITHDRAW the item to your bags (whole stack);
  Shift+Right-click withdraws exactly one. Because the working call
  into the realm's vault addon is not yet pinned down, withdrawal is a
  verified cascade: each plausible route (UncappedVault.Withdraw and
  .Send in both call styles, then the raw VLTWD wire verb) is tried in
  turn, the vault is re-read 1.5s after each, and the next route fires
  only if the item did not move — at most one route can ever take
  effect. The first route that works is remembered and used directly
  from then on. One withdrawal at a time; progress, success and
  failure all show in the status line.
- Hide flat-stat-only items (option, DEFAULT ON): items whose only
  matched effects are passive flat bonuses ("+24 Intellect",
  "Increases X by N" with no duration) are hidden. Each candidate
  spell's own tooltip is scanned once, client-side and instant; any
  unrecognised or duration-bearing text ("...for 30 sec") classifies
  as a real proc, so uncertainty always keeps an item visible. Mixed
  items stay listed showing their real procs; passive stats appear
  greyed in the row tooltip. The status line counts what was hidden.
- Instant open: the list now fills from UncappedVault's data the
  moment the window opens — no more ~6 second watchdog wait. VLTGET
  is still sent underneath; a wire snapshot always takes over if the
  realm ever starts answering.
- Live updates: while fed from UncappedVault, the list re-reads the
  data every 2 seconds while the window is open (change-detected, so
  no churn), so deposits and withdrawals show up on their own —
  including ProcHunter's own withdrawals.
- /ph dump now also reports the remembered withdraw route and the
  types of UncappedVault.Withdraw / .Send.

v1.1.0 (2026-09-11)
-------------------
- FIX: the first /ph after login was silently eaten — 3.3.5a frames are
  shown by default, so the lazily built window was created "shown" and
  the first toggle immediately hid it. The window now hides itself at
  the end of its build; the first press opens it.
- Minimap button (spyglass): click opens/closes the window, drag moves
  it anywhere — exact x/y offsets are saved, no rim snapping (radius
  placement breaks on scaled minimaps).
- Interface Options panel (Interface -> AddOns -> ProcHunter): an Open
  ProcHunter button, a Show minimap button tickbox, and a slash-command
  reference.
- UncappedVault fallback: if the server does not answer VLTGET within
  5 seconds, ProcHunter reads the UncappedVault addon's own items table
  directly (field names probed tolerantly; array, keyed-row and
  entry->count shapes all understood). The status line shows
  "source: UncappedVault" when this path fed the list. A wire snapshot,
  when one arrives, always takes over again.
- /ph debug — toggles printing of ALL addon wire traffic (any prefix)
  to chat, for diagnosing server behavior without /run scripts. A
  deliberate, opt-in exception to the no-chat-output rule.
- /ph dump — prints what _G.UncappedVault looks like (types, entry
  count, the first row's fields), so a failed fallback can be matched
  to reality from a screenshot.

v1.0.0 (2026-09-11)
-------------------
Initial release.

- Scans the Uncapped Vault and lists every item that is equippable by
  anyone (weapons and armor, including rings/trinkets/necks/cloaks/
  shields/relics; class and level restrictions deliberately ignored)
  AND carries an effect spell found in the bundled proc database.
- Bundled database: item -> proc mapping generated from the 3.3.5a
  item_template plus Spell/ItemSet DBCs (the SchoolPop ProcDB data,
  renamed into the ProcHunter namespace), plus the drop-source table.
  Fully standalone — no other addon required.
- Read-only on the wire: the only message ever sent is VLTGET, the
  same snapshot request the Dashboard's Vault tab sends. ProcHunter
  never deposits, withdraws, consumes or modifies anything.
- Live: VLTUPD/VLTROWUPD pushes from the server mark the list stale
  and it re-pulls (debounced) while the window is open. Snapshots
  streamed for other addons (e.g. opening the Dashboard vault tab)
  are absorbed for free.
- Window: draggable (position saved), Escape closes, Refresh button,
  live text filter matching item names and proc names, rows show
  icon / item level / quality-colored name with stack count / proc
  names; hovering a row shows the full item tooltip plus the proc
  list with spell IDs and drop sources.
- Uncached items are primed via a hidden tooltip and retried once per
  second (up to 20 tries); a "waiting on item cache" counter shows
  progress.
- Slash commands: /prochunter and /ph.
- Only chat output is the login stamp.

Known limitations (v1.0.0):
- The database is name-matched and generated from stock 3.3.5a data:
  custom Uncapped items whose names are not in it will not be flagged.
- Proc chance and imprinted (SoulForge) procs on specific vault copies
  cannot be shown — the vault wire stream carries no proc data and no
  server verb exposes it for vault items.
- The database does not distinguish chance-on-hit procs from on-use or
  on-equip effects, so use-effect trinkets and similar items are
  listed too.
