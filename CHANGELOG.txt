ProcHunter — Changelog
======================

v1.7.3 (2026-09-12)
-------------------
PROCS ONLY + ONE DONE RULE + LEARNED CUSTOM ITEMS

- FLAT EFFECTS NO LONGER AUTO-EXTRACT. Extract All and the tick math
  consider real procs only — stat-stick effects stop polluting your
  library. Flat-only items carry no tick and are never queued. A
  deliberate manual Ctrl+Right-click on one still works (untick
  "hide flat" to see them).
- ONE done predicate: ticked == done == hidden == skipped. The tick
  drawing, the auto-hide filter, and the Extract All queue now all
  consult the same single test and can never disagree — a ticked
  item cannot appear in the list (checkbox off) and cannot be queued.
- Items the bundled DB does not know are now LISTED once the wire
  has taught their spells (v1.7.2's entry map): they show as locked,
  extract normally, and hide when collected. ProcHunter's coverage
  converges on the server's own with every stream.

/reload suffices.

v1.7.2 (2026-09-12)
-------------------
CUSTOM SPELLS BRIDGED — ENTRY-KEYED LEARNING

Root cause of the stubborn "finished items still listed / nothing
left to learn" loop: the Uncapped server's custom spells (the whole
Twilight Scale line and friends) have IDs the stock client cannot
name — GetSpellInfo returns nothing. Names could never bridge the
bundled DB's stock IDs to the server's custom IDs, so those items
looked locked forever while every extraction correctly came back
"nothing left".

- The wire itself is now the bridge, keyed by ITEM ENTRY: every
  ICEXI row (entry + spell) and every ICCOLLROW source field teaches
  a persistent entry -> spell map. An entry whose known spells are
  all in your collection is DONE: green tick, auto-hidden, never
  queued — no names involved.
- A "nothing left to learn" verdict from a real attempt marks the
  entry done permanently. One wasted withdraw per item at absolute
  worst, then never again.
- Learning persists across sessions and grows on its own: every bag
  scan the Dashboard or ProcHunter triggers feeds it.

/reload, then open the SoulForge Collection tab once (or press
Refresh) so a collection stream teaches the map — the phantom
"locked" customs collapse to green and vanish.

v1.7.1 (2026-09-12)
-------------------
HOTFIX — EXTRACTED ITEMS RE-OPENED BY PHANTOM AURAS

v1.7.0 counted EVERY DB effect toward an item's green tick, including
passive auras that were never in the server's extraction system. Any
finished item carrying such an aura silently re-opened: it reappeared
in the list, the queue exploded (300+ -> 900+), and the runner burned
withdrawals on effects the server refuses ("unlock not confirmed").

- The tick / queue / expectation set is now the item's PROCS when it
  has any, and its flat effects only for flat-only items (Crafty's
  Pole class stays extractable). Never the union.
- Finished items are green and auto-hidden again; the queue is back
  to real work only. Copies the runner wasted were auto-redeposited
  by the existing machinery; nothing was lost, only time.

/reload suffices.

v1.7.0 (2026-09-12)
-------------------
BAGS IN THE SCAN + FLAT EXTRACTION + SPEED + FAILURE LOG

- Your BAGS are scanned alongside the vault. Bag copies show on the
  item's row as "(+N in bags)"; items you only hold in bags join the
  list too. Extracting a bag copy skips the withdraw stage entirely —
  straight to locate -> consent -> unlock. Vault stock is ALWAYS
  consumed first; a bag copy is only used when the vault has none,
  and only when exactly one is in bags. A pre-existing bag copy is
  YOURS: aborted flows leave it exactly where it was — only copies
  the addon itself withdrew are auto-redeposited. The list refreshes
  live on bag changes.
- "Flat" is now purely cosmetic. The server extracts ANY effect
  (fishing skill, stat effects, on-use), so tick math, the dialog,
  and Extract All consider every effect the DB knows (teleport/portal
  still excluded). The Extract All queue is drawn from the FULL scan:
  the hide-flat display filter can no longer hide work from the
  runner. Crafty's Pole class items now extract.
- ADAPTIVE PACING: flows run at 0.6s gaps and 3s timeouts until the
  server pushes back (DSAERR, ICERR, or an unanswered request), then
  back off to 2.5s/5s and 6s timeouts, recovering after three clean
  flows. Clean runs are several times faster than v1.6.x.
- LOG button (top right): every failed or skipped extraction is kept
  (up to 200, across sessions) with time, item, entry ID, reason, and
  the wire traffic captured during that flow. Select-all + Ctrl+C
  friendly — paste it to Claude as-is. Clear button included.

/reload suffices.

v1.6.3 (2026-09-11)
-------------------
AUTO-HIDE EXTRACTED + DEPOSIT BAGS

- Fully-extracted items (every extractable proc name owned) are now
  hidden from the list by default — nothing left to do with them.
  A "show extracted" tickbox next to the filter brings them back;
  the choice is remembered. Teleport-only items (nothing extractable
  at all) stay visible.
- New "Deposit Bags" button: one confirm, then a single VLTDEPALL —
  the server-side bulk deposit. The server decides what qualifies;
  equipped gear and non-vault items stay untouched. For when a long
  session fills your inventory.

/reload suffices.

v1.6.2 (2026-09-11)
-------------------
DEPOSIT VERIFICATION + NAME-BASED OWNERSHIP

- Redeposits are now VERIFIED. An unanswered extractor usually means
  the server is throttling this client, and the same throttle could
  eat the immediate VLTDEP — the copy silently stayed in your bags.
  The slot is now watched: still holding the item 2.5s later, the
  deposit is re-sent, up to 4 attempts spaced past any throttle
  window. If the vault never accepts, the addon says so honestly:
  "deposit not accepted — <item> left in your bags". Extract All
  pauses while a redeposit is in flight.
- Ownership is judged by proc NAME everywhere, not spell ID. The
  server's collection stores its own rank IDs; when they differ from
  the bundled DB's, items showed locked forever and every extract
  came back "nothing left to learn". Now any owned rank of a name
  counts in the tick math, the dialog greying, and Extract All's
  queue — fully-learned items turn green the moment the collection
  loads and are never offered again.

/reload suffices.

v1.6.1 (2026-09-11)
-------------------
PORTAL RULE + AUTO-REDEPOSIT

- Portal procs (Atiesh-style "Creates a portal...") are now caught by
  the unextractable rule alongside teleports: greyed in the dialog,
  never auto-picked, skipped by Extract All, excluded from the tick.
- Any flow that ends with an unextractable copy in your bags sends it
  STRAIGHT back to the vault (VLTDEP, the pack's own deposit verb).
  Covers: nothing left to learn, server refused, no proc reported,
  locate timeout, and the several-copies abort. Your explicit Cancel
  still keeps the copy in bags — that is a choice, not a failure.
- A copy with nothing learnable no longer opens the dialog at all:
  it goes back immediately with a status note.
- Net effect with Extract All: a full run leaves your bags exactly as
  it found them — the closest thing to extracting straight from the
  vault the server allows (there is no vault-side extraction verb).

/reload suffices.

v1.6.0 (2026-09-11)
-------------------
EXTRACT ALL + TELEPORT RULE

- New "Extract All" button next to Refresh. One consent dialog, then
  an unattended run: per item — withdraw one copy, learn its first
  still-locked proc, repeat until the item is fully green, next item.
  One vault copy is destroyed per proc learned. Paced ~2.5s between
  flows for the server throttle. The button turns into Stop; pressing
  it ends the run after the current item. Failed flows skip the item
  and the run continues; every skip is reported in chat with a reason
  at the end. Items with copies already in your bags are skipped
  (single-copy safety rule) — deposit them and rerun.
- Server rule honored: TELEPORT procs cannot be extracted. Greyed in
  the Destroy & Learn dialog with the reason, never auto-picked,
  skipped by Extract All, and excluded from the green-tick math — an
  item whose only proc teleports needs nothing extracted.

/reload suffices.

v1.5.3 (2026-09-11)
-------------------
SERVER BAG NUMBERING FIX — the pushed stream was heard (v1.5.2's
cache worked) but the server numbers bags/slots differently than the
client, so the pinned bag:slot never matched any ICITEM:B header and
the flow aborted with "no extractable proc".

- Resolution now falls back to matching buckets by the item's OWN
  proc names (from the DB — the reason it is listed at all). Rank
  variants count, same as ticks.
- The fallback is accepted ONLY while exactly one copy of the item
  is in your bags: only then can the matching bucket BE the fresh
  copy. Otherwise the flow aborts with "several copies of this item
  are in your bags — keep exactly ONE, then retry". A pre-existing,
  possibly imprinted copy is never put at risk.
- ICUNLOCK now echoes the server's own coordinates from the stream
  back at it, whatever its numbering is.

IMPORTANT after the failed attempts today: your bags likely hold
several withdrawn copies of the item you tested. Deposit the extras
back into the vault (keep NONE), then Ctrl+Right-click once.

v1.5.2 (2026-09-11)
-------------------
EXTRACTION RACE FIX — the real reason Ctrl+Right-click still looked
like a plain withdraw: the live realm PUSHES the ICINV proc stream
the instant the withdrawn copy lands, BEFORE the bag diff has pinned
the slot. v1.5.1 only listened during the locate stage, so the push
was dropped and the late request went unanswered.

- The stream (both dialects) is now cached for the whole life of the
  flow, bucketed per bag:slot. Once the slot is pinned, a cache hit
  opens the consent dialog instantly — no request needed at all.
- Cache miss still sends ICEXSRC + ICINV as before (old-pack realms).
- An END line arriving during the withdraw stage closes the cache and
  never aborts. A locate timeout salvages cached rows if the END line
  itself got lost.
- Version is now visible: window title, login message, and /ph dump
  all say the real version (v1.5.1 wrongly announced itself as
  v1.5.0 at login — the stamp was missed; the .toc was correct).

/reload suffices.

v1.5.1 (2026-09-11)
-------------------
LIVE-REALM EXTRACTION FIX — Ctrl+Right-click looked like a plain
withdraw because the live realm never answers ICEXSRC; it speaks a
different wire dialect for bag proc queries.

- The locate stage now asks in BOTH dialects: ICEXSRC (old pack) and
  ICINV (live realm).
- The parser understands both replies: classic ICEXI rows, and the
  live realm's ICITEM:B:<bag>:<slot> headers followed by
  ICIPROC:<spell>:<trigger> rows, closed by ICINVEND. Only rows under
  the header of YOUR pinned bag slot are read; equipped-gear headers
  and other slots are ignored, as is ICIPROCBP/FACT/SRC/STAT noise.
- If a realm ever answers both dialects, duplicate procs are deduped.
- Everything downstream is untouched: consent dialog, slot
  re-verification at confirm, ICUNLOCK, live tick flip.

/reload suffices.

v1.5.0 (2026-09-11)
-------------------
EXTRACT FROM THE LIST — Ctrl+Right-click a row to learn one of its
procs, end to end:

- ProcHunter withdraws one copy, identifies the EXACT bag slot it
  landed in (bag snapshot diff: only a slot that newly gained the
  item can ever be destroyed — a pre-existing, possibly imprinted
  copy is never touched), asks the extraction picker (ICEXSRC ->
  ICEXI ... ICEXIEND) for the copy's exact spell and trigger, and
  opens a NAMED CONSENT DIALOG.
- The dialog lists the copy's procs; ones already unlocked are
  greyed out, the first learnable one is pre-selected, and the
  warning is explicit: "This DESTROYS the withdrawn copy. One proc
  per copy." Extraction is free on this realm (Scrolls of Extraction
  are retired) — nothing else is spent.
- Confirm re-verifies the bag slot at the moment of truth (any drift
  aborts with nothing destroyed) and sends ICUNLOCK. On the server's
  ICUNLOCKED reply the proc joins your collection instantly and the
  item's tick flips green live — Wardrobe unlocks made outside
  ProcHunter are absorbed the same way.
- Every stage has a timeout that aborts loudly with the item safe in
  your bags; Cancel does the same. If every proc on the copy is
  already unlocked, the confirm button is disabled and the copy
  simply stays with you. One flow at a time; live progress in the
  status line.

Built from the dissected server addon pack (uploaded 2026-09-11):

  yellow tick when only some are. Judged per proc NAME, so owning any

  fallback was removed server-side) — which is why the UNC listener

  is still heard and nudges kirei's addon to refresh the very table

v1.2.0 (2026-09-11)
-------------------
- Right-click a row to WITHDRAW the item to your bags (whole stack);
  Shift+Right-click withdraws exactly one. Because the working call
  into the realm's vault addon is not yet pinned down, withdrawal is a
  verified cascade: each plausible route (UncappedVault.Withdraw and
  .Send in both call styles, then the raw VLTWD wire verb) is tried in
  turn, the vault is re-read 1.5s after each, and the next route fires
  only if the item did not move — at most one route can ever take
  effect. The first route that works is remembered and used directly
  from then on. One withdrawal at a time; progress, success and
  failure all show in the status line.
- Hide flat-stat-only items (option, DEFAULT ON): items whose only
  matched effects are passive flat bonuses ("+24 Intellect",
  "Increases X by N" with no duration) are hidden. Each candidate
  spell's own tooltip is scanned once, client-side and instant; any
  unrecognised or duration-bearing text ("...for 30 sec") classifies
  as a real proc, so uncertainty always keeps an item visible. Mixed
  items stay listed showing their real procs; passive stats appear
  greyed in the row tooltip. The status line counts what was hidden.
- Instant open: the list now fills from UncappedVault's data the
  moment the window opens — no more ~6 second watchdog wait. VLTGET
  is still sent underneath; a wire snapshot always takes over if the
  realm ever starts answering.
- Live updates: while fed from UncappedVault, the list re-reads the
  data every 2 seconds while the window is open (change-detected, so
  no churn), so deposits and withdrawals show up on their own —
  including ProcHunter's own withdrawals.
- /ph dump now also reports the remembered withdraw route and the
  types of UncappedVault.Withdraw / .Send.

v1.0.0 (2026-09-11)
-------------------
Initial release.

- Scans the Uncapped Vault and lists every item that is equippable by
  anyone (weapons and armor, including rings/trinkets/necks/cloaks/
  shields/relics; class and level restrictions deliberately ignored)
  AND carries an effect spell found in the bundled proc database.
- Bundled database: item -> proc mapping generated from the 3.3.5a
  item_template plus Spell/ItemSet DBCs (the SchoolPop ProcDB data,
  renamed into the ProcHunter namespace), plus the drop-source table.
  Fully standalone — no other addon required.
- Read-only on the wire: the only message ever sent is VLTGET, the
  same snapshot request the Dashboard's Vault tab sends. ProcHunter
  never deposits, withdraws, consumes or modifies anything.
- Live: VLTUPD/VLTROWUPD pushes from the server mark the list stale
  and it re-pulls (debounced) while the window is open. Snapshots
  streamed for other addons (e.g. opening the Dashboard vault tab)
  are absorbed for free.
- Window: draggable (position saved), Escape closes, Refresh button,
  live text filter matching item names and proc names, rows show
  icon / item level / quality-colored name with stack count / proc
  names; hovering a row shows the full item tooltip plus the proc
  list with spell IDs and drop sources.
- Uncached items are primed via a hidden tooltip and retried once per
  second (up to 20 tries); a "waiting on item cache" counter shows
  progress.
- Slash commands: /prochunter and /ph.
- Only chat output is the login stamp.

Known limitations (v1.0.0):
- The database is name-matched and generated from stock 3.3.5a data:
  custom Uncapped items whose names are not in it will not be flagged.
- Proc chance and imprinted (SoulForge) procs on specific vault copies
  cannot be shown — the vault wire stream carries no proc data and no
  server verb exposes it for vault items.
- The database does not distinguish chance-on-hit procs from on-use or
  on-equip effects, so use-effect trinkets and similar items are
  listed too.
